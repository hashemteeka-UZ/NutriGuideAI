## 2. تشغيل الخادم

### 2.1 أول مرة فقط (⁨Terminal⁩ داخل ⁨WSL⁩)
1. انتقل إلى المشروع وأنشئ ملف الإعدادات من المثال:
```bash
cd ~/NutriGuideAI
cp .env.example .env
```
2. ضع في ملف .env قيمة ⁨JWT_SECRET⁩ لا تقل عن 32 حرفًا. هذا الأمر يولد لك واحدة، انسخ الناتج إلى الملف:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```
3. شغّل قاعدة البيانات وتأكد أنها تعمل (يجب أن تظهر ⁨healthy⁩):
```bash
docker compose up -d db
docker compose ps
```
4. ثبت حزم الخادم وابنِ قاعدة البيانات بالبيانات الكاملة:
```bash
cd backend
uv sync
uv run python -m scripts.rebuild_dev_db --yes
```

### 2.2 كل مرة (⁨Terminal⁩ داخل ⁨WSL⁩)
1. تأكد أن ⁨Docker Desktop⁩ يعمل على ⁨Windows⁩.
2. شغّل قاعدة البيانات ثم الخادم:
```bash
cd ~/NutriGuideAI
docker compose up -d db
cd backend
uv run uvicorn app.api.main:app --host 0.0.0.0 --port 8000
```
3. تحقق من أن الخادم يعمل بفتح هذا الرابط في المتصفح، ويجب أن يظهر "⁨status⁩": "⁨ok⁩":
```
http://localhost:8000/api/v1/health
```
4. وثيقة الواجهة التفاعلية (⁨Swagger⁩) على:
```
http://localhost:8000/api/docs
```

### 2.3 تشغيل الاختبارات (⁨Terminal⁩ داخل ⁨WSL⁩)
```bash
cd ~/NutriGuideAI
docker compose --profile test up -d db_test
cd backend
```

## 3. تثبيت التطبيق على هاتف

التفاصيل الكاملة في ملف INSTALL_APK.md في المستودع:
```
mobile/docs/INSTALL_APK.md
```
وهذا ملخصها:
1. شغّل الخادم كما في القسم 2.2 (⁨Terminal⁩ داخل ⁨WSL⁩).
2. اسمح للهاتف بالوصول إلى الخادم عبر الشبكة. افتح ⁨PowerShell⁩ كمسؤول (⁨Run as administrator⁩) ونفذ:
```powershell
$wsl = (wsl hostname -I).Trim().Split(' ')[0]
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8000 connectaddress=$wsl connectport=8000
```
3. بعد كل إعادة تشغيل للحاسوب يتغير عنوان ⁨WSL⁩، فاحذف التحويل القديم ثم أعد الخطوة 2:
```powershell
netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8000
```
4. اعرف عنوان الحاسوب على شبكة ⁨Wi-Fi⁩ بالأمر ⁨ipconfig⁩ في ⁨PowerShell⁩ (سطر ⁨IPv4 Address⁩)، ثم افتح من متصفح الهاتف (بعد وضع عنوانك):
```
http://<PC-IP>:8000/api/v1/health
```
5. انقل ملف ⁨APK⁩ إلى الهاتف وثبته، واسمح بالتثبيت من مصدر غير معروف لهذه المرة فقط.
6. يجب أن يكون الهاتف على شبكة ⁨Wi-Fi⁩ نفسها التي عليها الحاسوب.

### 3.1 إعادة بناء التطبيق بعنوان خادم جديد (⁨PowerShell⁩ على ⁨Windows⁩)
عنوان الخادم مثبت داخل التطبيق وقت البناء. النسخة الحالية مبنية على العنوان:
```
http://172.17.175.48:8000
```
إذا تغير عنوان حاسوبك، أضف العنوان الجديد إلى ملف إعدادات الشبكة أولًا (يسمح بالاتصال غير المشفر للعناوين المحلية المذكورة فيه فقط):
```
mobile/android/app/src/main/res/xml/network_security_config.xml
```
ثم ابنِ من جديد:
```powershell
cd C:\dev\NutriGuideAI\mobile
flutter build apk --release --dart-define=API_BASE_URL=http://<PC-IP>:8000
```
وعند الاستضافة لاحقًا، ابنِ بعنوان ⁨HTTPS⁩ واحذف العناوين المحلية من ملف إعدادات الشبكة:
```powershell
flutter build apk --release --dart-define=API_BASE_URL=https://<domain>
```

## 4. مشكلة مفتاح ⁨SSH⁩ في ⁨WSL⁩

منذ 2026-10-25 يرفض ⁨GitHub⁩ مفتاح ⁨SSH⁩ الموجود داخل ⁨WSL⁩، فكان الرفع (⁨git push⁩) يتم من نسخة ⁨Windows⁩، ثم تُحدّث نسخة ⁨WSL⁩ منها. والسبب الأرجح أن المفتاح غير محمّل في ⁨ssh-agent⁩ بعد إعادة التشغيل، لأن عليه كلمة مرور. لإصلاحها (⁨Terminal⁩ داخل ⁨WSL⁩):
1. اختبر الاتصال:
```bash
ssh -T git@github.com
```
2. إن ظهر ⁨Permission denied⁩، حمّل المفتاح ثم أعد الاختبار:
```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
ssh -T git@github.com
```
3. إن بقي الرفض، فالمفتاح العام ربما حُذف من حسابك على ⁨GitHub⁩. اعرضه وأضفه من جديد في إعدادات ⁨GitHub⁩ (⁨SSH and GPG keys⁩):
```bash
cat ~/.ssh/id_ed25519.pub
```
4. ملاحظة: إذا كان اسم ملف المفتاح عندك مختلفًا، اعرف اسمه بالأمر ⁨ls⁩ ~/.⁨ssh⁩ واستخدمه بدل ⁨id_ed25519⁩.
5. قبل أي عمل في ⁨WSL⁩، حدّث النسخة من ⁨GitHub⁩ حتى لا تختلف عن نسخة ⁨Windows⁩:
```bash
cd ~/NutriGuideAI
git pull origin main
```

## 5. ما الذي بقي

### 5.1 الاستضافة (مؤجلة بقرارك)
- الشرط: مجانية. واختيارك المبدئي كان ⁨Oracle Cloud Always Free⁩ للتجربة قبل المناقشة، مع إمكانية التغيير إن ظهرت مشكلات.
- ما يحتاجه الخادم: نواة معالج كاملة على الأقل (المُحسِّن يستهلك المعالج)، وذاكرة 1 غيغابايت فأكثر، و⁨PostgreSQL⁩ 16 بتخزين دائم ونسخ احتياطي، و⁨HTTPS⁩، ولا ينام الخادم عند عدم الاستخدام.
- تنبيهات ⁨Oracle⁩: قد تظهر رسالة نفاد السعة فتعيد المحاولة، وقد تُستعاد الأجهزة الخاملة، والمعالج ⁨ARM⁩ فيجب التأكد من عمل مكتبة ⁨ortools⁩ عليه.
- وعند الاستضافة يُضاف: ⁨HTTPS⁩، وإعداد ⁨CORS⁩، ونسخ احتياطي يومي لقاعدة البيانات خارج الخادم، وفحص الحزم (⁨pip-audit⁩)، ثم إعادة بناء التطبيق بعنوان ⁨HTTPS⁩ (القسم 3.1).

### 5.2 خطوات التحضير لـ 37 وجبة
وجبات الدفعة الأولى الـ 37 ليس لها خطوات تحضير بعد (121 وجبة من 158 لها خطوات). تحتاج من الفريق كتابتها، ثم تُضاف بالمسار نفسه المستخدم في باقي الدفعات.

### 5.3 التجربة مع الفريق والمستخدمين
- الهدف: جمع بيانات استخدام حقيقية لتقييم طبقة التعلم على سلوك حقيقي بدل المحاكاة.
- ما يمكن الآن دون استضافة: تجربة محدودة للفريق على شبكة ⁨Wi-Fi⁩ نفسها (القسم 3).
- ما يحتاج الاستضافة: تجربة أوسع لمستخدمين من أماكن مختلفة.
- بعد جمع البيانات: تقييم ⁨LinUCB⁩ بإعادة الأحداث المسجلة، واستبيان قابلية الاستخدام ⁨SUS⁩، ومقارنة الإصدار المتعلم بالإصدار دون تعلم. وكل هذا مذكور في الفصل الخامس كعمل مستقبلي.

### 5.4 التقرير
- مسودة الفصول من 1 إلى 5 جاهزة. وتحتاج من الفريق: مراجعة اللغة، وإضافة صفحة الغلاف والإهداء والشكر وفق نموذج الكلية، وتحديث فهرس المحتويات من ⁨Word⁩ (⁨References⁩ ثم ⁨Update Table⁩)، وأي ملاحظات من المشرف.
- مصادر التقرير (ملفات النص وسكربت البناء) في مجلد ⁨build⁩، فإن عُدّل النص يمكن إعادة بناء الملف بأمر واحد:
```bash
cd deliveries/final/build
python3 build_report.py ch_abstract_1_2.src.md ch3.src.md ch4.src.md ch5.src.md ../NutriGuideAI_Report_Ch1-5.docx ../references.txt
```

### 5.5 ميزات مؤجلة بقرارك
