## 1. `app/services/meal_nutrition.py` — calc_v1 (§10.3)

- `COMPUTATION_VERSION = "calc_v1"`.
- `compute_meal_nutrients(session, meal_id, now) -> MealNutritionResult`: for **every** nutrient in `nutrients` (mandatory and not):
  - `total(n) = Σ over meal_ingredients (grams / 100) × food_nutrients.amount_per_100g(food_id, n)`.
  - If **any** ingredient has `food_id IS NULL`, or its food has no `food_nutrients` row for `n`, the total for `n` is **unknown**: write no `meal_nutrients` row for `n` (missing ≠ zero, §9.8). Never treat a missing value as 0.
  - `amount_per_serving = total / meals.servings`; `amount_per_100g = total / meals.total_grams × 100`.
  - Replace the meal's `meal_nutrients` rows (delete then insert, or diff), with `computed_at = now`, `computation_version = 'calc_v1'`.
  - Return which mandatory nutrients are missing; `is_complete` = none missing.
- `is_meal_nutritionally_complete(session, meal_id) -> bool`: true iff a `meal_nutrients` row exists for every `is_mandatory` nutrient (used by Layer 1 rule 1 in pass F.1-c).
- Rounding: keep full precision in Python (`Decimal` or float), let `NUMERIC(12,3)` round on insert; tests compare with a 0.001 tolerance.

## 2. `app/services/meal_derived.py` — `recompute_meal_derived(session, meal_id)` (§10.4, §10.5, rule R1)

- `meal_allergens`: fully rebuilt as the union of `ingredient_allergens` of the meal's ingredients.
- `meal_tags` with `source = 'DERIVED'`: delete and rebuild **only** `DERIVED` rows; never touch `MANUAL` rows except as stated below. The derived set is:
  1. **Ingredient union (presence properties):** the union of the ingredients' `ingredient_tags` whose tag has `tag_group = 'CONDITION'` (e.g. `added_sugar`). `DIETARY` ingredient tags are **not** unioned (a vegan ingredient does not make a meal vegan).
  2. **Rule R1, meal-level thresholds (decision for finding F-02):** threshold tags are derived from the meal's own `meal_nutrients.amount_per_100g`, not from ingredients, because a pinch of salt would otherwise tag every savoury meal `high_sodium`. Define them as code constants in `app/services/tag_rules.py`:
     ```python
     TAG_RULES_VERSION = "tags_v1"
     # UK Food Standards Agency front-of-pack "high" thresholds per 100 g.
     THRESHOLD_TAGS = {"high_sodium": ("sodium", 600), "high_sugar": ("sugars", 22.5)}
     ```
     A meal gets the tag when `amount_per_100g > threshold`. If the nutrient is unknown for the meal, the tag is **not** derived and the result reports it.
  - If a `MANUAL` row exists for a tag that is also derived, it is replaced by the `DERIVED` row (§10.5).
  - A threshold tag code must never appear in `ingredient_tags`; if it does, raise an error (data error, not a silent skip).
- Run order for a meal: `compute_meal_nutrients` first, then `recompute_meal_derived`.

## 5. `app/services/targets.py` — targets_v1 (§30.2–§30.4b, §30.6)

- `FORMULA_VERSION = "targets_v1"`. All constants in one module-level block with the section number in a comment.
- Pure function `compute_targets(inputs: TargetInputs) -> TargetResult` (no DB). Inputs: sex, age (years), height_cm, weight_kg, activity_level, goal_type, weekly_rate_kg (nullable), target_weight_kg (nullable).
  1. BMR (Mifflin-St Jeor): men `10W + 6.25H − 5A + 5`, women `10W + 6.25H − 5A − 161`.
  2. TDEE = BMR × PAL (`SEDENTARY 1.2, LIGHT 1.375, MODERATE 1.55, HIGH 1.725, ATHLETE 1.9`).
  3. `LOSE`: effective rate = min(weekly_rate_kg, 0.01 × W); deficit = min(rate × 7700 / 7, 1000); target = TDEE − deficit. `GAIN`: effective rate = min(weekly_rate_kg, 0.5); surplus = min(rate × 7700 / 7, 500); target = TDEE + surplus. `MAINTAIN`: target = TDEE. Report `rate_was_capped`.
  4. Floor: women 1200, men 1500; if applied, `was_floor_applied = True`.
  5. Round `target_kcal` to the nearest whole kcal **before** the macros.
  6. Protein (§30.4): g/kg = `LOSE 1.4`, `MAINTAIN 1.0`, `GAIN 1.8`; `ATHLETE` activity → 1.8 whatever the goal. Reference weight: `BMI = W / (H/100)²`; BMI < 30 → W; else `IBW = 25 × (H/100)²` and reference = `IBW + 0.4 × (W − IBW)`. protein_g = g/kg × reference.
  7. Fat 30% of energy (fat_g = 0.30 × kcal / 9). Carbohydrate = (kcal − 4·protein − 9·fat) / 4.
  8. Minimum 130 g carbohydrate (§30.4, #67). If below: (a) lower fat **only as much as needed**, but not below 25% of energy; (b) if still below, lower protein only as much as needed, but not below the low end of its range (`LOSE 1.2`, `GAIN`/`ATHLETE 1.6` g/kg × reference; `MAINTAIN` has no range, so no change); (c) if still below, keep the result and log a warning with the user inputs (no exception). Report which steps were applied.
  9. Fiber (§30.4b) is returned (`round(14 × kcal / 1000)`) but **not stored**.
  10. Stored precision: `bmr_kcal`, `tdee_kcal` to 1 decimal; `target_kcal` whole; protein/fat/carb grams to 1 decimal.
- DB service `create_user_target(session, user_id, reason, now) -> UserTarget`: reads the profile and the **latest** `weight_logs` row (by `measured_on`); computes age at `now`'s date in `user_profiles.timezone`; closes the current row (`valid_to = now`) and inserts the new one (`valid_from = now`, `valid_to = NULL`, `based_on_weight_kg`, `formula_version`, `reason`, `was_floor_applied`) in the same transaction, so the partial unique index (one current target per user) always holds. Raises a clear error if there is no weight row or the user fails screening (targets are only for eligible users).
- Validation (application logic, §11.2): `LOSE` requires target_weight < current weight; `GAIN` requires target_weight > current weight. Raise a clear error otherwise.
