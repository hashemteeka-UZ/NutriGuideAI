## 2. Adaptive steps (#236)
The step list is computed from the answers (pure function, like `steps()` in the prototype, minus the cancelled steps):
1. `about`: sex (MALE/FEMALE, two large cards) and birth date (section 3).
2. `measure`: height (cm, 100-250, step 1) and current weight (kg, 20-400, step 0.5) as wheels; a live BMI card (`bmiCard()` style: value, label «أقل من الطبيعي / طبيعي / فوق الطبيعي / مرتفع» at 18.5/25/30, coloured scale) with an expandable «ما هو مؤشر كتلة الجسم؟».
3. `goal`: LOSE «إنقاص الوزن» / MAINTAIN «المحافظة على وزني» / GAIN «زيادة الوزن», with the prototype subtitles (GAIN subtitle: «فائض مدروس في السعرات», not the protein text).
4. `pace` (only if LOSE or GAIN): target weight wheel + pace options + estimated arrival (section 4). Show the adaptive badge «سؤال خاص بك · لأن هدفك تغيير الوزن».
5. `activity`: SEDENTARY, LIGHT, MODERATE, HIGH, ATHLETE with the prototype titles and subtitles.
6. `care`: conditions from `/reference` where `is_supported == true` (multi-select) plus «لا شيء · أريد أكلًا صحيًا ومتوازنًا فقط» (exclusive). Expandable «كيف نراعي ذلك؟» with the prototype explanation. Wellness tone: we avoid worsening, we do not treat.
7. `allergy`: allergens from `/reference` as a 3-column grid; tap once = `AVOID` «تجنب», twice = `SEVERE` «شديدة», third tap clears. Subtitle «اضغط مرة للتجنب، ومرتين إذا كانت حساسية شديدة».
8. `safety` (only if `DIABETES_T2` selected): «سؤال أخير للاطمئنان» / «هل تستخدم الإنسولين؟» Yes/No, with «لماذا نسأل؟» explaining that insulin users need carbohydrate planning tied to their doses, which this app does not cover, so they get the general mode. Yes adds `{code: DIABETES_INSULIN}` to `conditions`.
9. `rhythm`: wake time and sleep time (`HH:MM`, 15-minute steps; defaults 07:00 and 23:00), with a small "your suggested day" preview of meal windows text only (no training items).
10. `fluid` (only if a selected condition has `fluid_goal_requires_clinician == true`, today `HEART_DISEASE`): «متابعة الماء مع طبيبك». Option A «لم يحدد لي طبيبي كمية» -> `water_goal_ml: null`. Option B «حدد لي طبيبي كمية يومية» -> number field 500-5000 ml -> `water_goal_ml`.
11. `submit + result` (section 5 and 6).
Buttons «متابعة» and «رجوع»; Android back goes to the previous step; the progress bar reflects the current computed list. Changing an earlier answer recomputes the list (e.g. switching to MAINTAIN removes `pace` and clears target weight and rate). Each step's «متابعة» is disabled until its answer is valid.

## 4. Pace and target weight (#238)
- Rates: LOSE offers 0.25 «هادئة · الأسهل للاستمرار», 0.5 «متوازنة · ننصح بها» (default), 0.75 «أسرع», 1.0 «الأقصى». An option whose rate is above 1% of the current weight is disabled with «غير متاحة لوزنك الحالي (أكثر من 1% أسبوعيًا)». GAIN offers 0.25 and 0.5 (default 0.25) with the note «الحد الآمن للزيادة نصف كغ أسبوعيًا». These mirror the server caps (1% of body weight per week for loss, 0.5 kg for gain) so the user never picks a rate the server would silently reduce.
- Target weight: LOSE must be below the current weight, GAIN above it; overall 30-300 kg; step 0.5. **Safety rule (app side): for LOSE the lowest selectable target is the weight at BMI 18.5 for the entered height** (round up to the next 0.5 kg). Show the reason under the wheel: «لا نقترح هدفًا أقل من الوزن الطبيعي لطولك». If the current weight is already at or below that weight, LOSE is not offered in step 3 (show it disabled with the same reason).
- Estimated arrival: weeks = ceil(|current - target| / rate); show «تصل إلى X كغ بعد نحو N أسبوعًا، تقريبًا في <month> <year>» (gendered, section 7), month names from `intl`.
- All of this is in `pace_rules.dart` with unit tests (boundaries: 1% exactly, BMI 18.5 rounding, MAINTAIN has no rate/target).
