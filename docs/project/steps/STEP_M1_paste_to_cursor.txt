## 1. Queue methods (#301) — interaction_queue.dart
- `rate({required int mealId, required int value, int? planItemId, required String screen})`: asserts 1 <= value <= 5 (throw ArgumentError otherwise); random client uuid (a new rating is a new event; the server replays all).
- `skip({required int planItemId, required int mealId, required String date})`: deterministic uuid v5 from 'https://nutriguide.app/skip/<planItemId>:<date>' + entityRef 'skip:<planItemId>:<date>' (same pattern as impression), so a second tap or a restart cannot create a second SKIP.
- Unit tests: JSON of each op (event_type, value, plan_item_id, screen), value 0 and 6 rejected, SKIP dedupe in memory and via outbox entityRef.

## 2. Rating UI (#302)
- After the user logs a plan item as eaten (the existing log action on Today and on the plan item screen), show a small bottom sheet: title ar "كيف كانت الوجبة؟" / en "How was this meal?", five tappable stars (48 dp targets, semantics labels "1 من 5" etc.), and a text button ar "لاحقًا" / en "Later" that just closes it. Tapping a star queues RATE with that value and closes the sheet with a short snackbar ar "شكرًا، سنقترح ما يناسب ذوقك أكثر" / en "Thanks, we'll suggest more of what you like".
- Plan item screen: for an item already logged as eaten, show a "قيّم الوجبة" / "Rate this meal" row with the same five stars; the chosen value is kept in an in-memory Riverpod map keyed by planItemId so the stars stay filled while the app runs (no schema change; after restart the stars are empty again and a new rating is simply a new event; note this in the report).
- Widget tests: sheet appears after logging, star 4 queues RATE value 4, "Later" queues nothing, plan item row shows filled stars after rating.

## 3. "Did not eat it" (#303)
- Plan item screen: for an item whose date <= today (device local date) and that is NOT logged, a secondary button ar "لم آكلها" / en "I didn't eat it". Tap -> confirm dialog (ar "سنقلل اقتراح هذه الوجبة قليلًا. متابعة؟" / en "We'll suggest this meal a little less. Continue?") -> queue SKIP -> button becomes a disabled chip ar "سُجلت: لم تؤكل" / en "Marked: not eaten". Do not offer it for future dates or logged items.
- Widget tests: visible only in the right states; confirm queues one SKIP; cancel queues nothing; second tap impossible.
