def get_db() -> Iterator[Session]:

`schemas/common.py`:

class ValidationIssue(BaseModel):

class ProblemDetail(BaseModel):

`errors.py`:
- `class ApiError(Exception)` with `status: int`, `code: str`, `title: str`, `detail: str | None`, `reasons: list[str] | None`, `headers: dict[str, str] | None`.
- `problem_response(status, code, title, detail=None, *, errors=None, reasons=None, headers=None) -> JSONResponse` that fills `request_id` from the request-id context (section E) and sets the media type.
- `SERVICE_ERRORS: Mapping[type[Exception], tuple[int, str]]` - the single table that maps domain exceptions to HTTP. Fill it with every one of these classes, importing each from where it is really defined (verify every name and module; if one does not exist, stop and report it instead of inventing it):

| exception | status | code |
|---|---|---|
| `ProfileNotFoundError` | 404 | `PROFILE_NOT_FOUND` |
| `MealNotFoundError` | 404 | `MEAL_NOT_FOUND` |
| `FoodNotFoundError` | 404 | `FOOD_NOT_FOUND` |
| `LogNotFoundError` | 404 | `LOG_NOT_FOUND` |
| `PlanItemNotFoundError` | 404 | `PLAN_ITEM_NOT_FOUND` |
| `UserNotEligibleError` | 409 | `NOT_ELIGIBLE` |
| `MissingTargetError` | 409 | `NO_TARGET` |
| `MissingWeightError` | 409 | `NO_WEIGHT` |
| `ConditionConflictError` | 409 | `CONDITION_CONFLICT` |
| `PlanItemAlreadyLoggedError` | 409 | `PLAN_ITEM_ALREADY_LOGGED` |
| `ClientUuidConflictError` | 409 | `CLIENT_UUID_CONFLICT` |
| `NoFeasiblePlanError` | 422 | `NO_FEASIBLE_PLAN` |
| `IncompleteNutritionError` | 422 | `INCOMPLETE_NUTRITION` |
| `SwapRejectedError` | 422 | `SWAP_REJECTED` |
| `ClockSkewError` | 422 | `CLOCK_SKEW` |
| `TargetValidationError` | 422 | `TARGET_VALIDATION` |
| `InvalidTimezoneError` | 422 | `INVALID_TIMEZONE` |

- Lookup walks the raised exception's MRO and uses the first class found in the table, so a subclass maps by its most specific entry (e.g. `PlanItemNotFoundError` is also a `LookupError`; it must map to `PLAN_ITEM_NOT_FOUND`).
- `reasons`: `UserNotEligibleError.reasons` and `SwapRejectedError.exclusion_codes` go into `reasons`. `detail` for mapped service errors = `str(exc)`.
- Handlers registered by `register_exception_handlers(app)`:
  1. `ApiError` -> its fields.
  2. One handler for `Exception` that first tries `SERVICE_ERRORS`; if the exception is mapped it returns that problem; otherwise it logs the exception with stack trace (`logger.exception`) and returns 500 `INTERNAL_ERROR`, title "Internal server error", no detail (never leak internals).
  3. `RequestValidationError` -> 422 `VALIDATION_ERROR`, `errors` = one `ValidationIssue` per pydantic error (`loc`, `msg`, `type`).
  4. `starlette.exceptions.HTTPException` -> same status, code from a small map: 401 `UNAUTHORIZED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 405 `METHOD_NOT_ALLOWED`, 429 `RATE_LIMITED`, 501 `NOT_IMPLEMENTED`, 503 `SERVICE_UNAVAILABLE`, otherwise `HTTP_<status>`; keep its headers.
- Also export `PROBLEM_RESPONSES: dict[int | str, dict[str, Any]]` - an OpenAPI `responses=` fragment declaring `ProblemDetail` with media type `application/problem+json` for 422 and `default`, so every router documents the error shape in the contract. Use it on the health router.

## E. Observability: `app/api/observability.py` (#133)
- `request_id_var: ContextVar[str | None]`.
- `RequestIdMiddleware` as a pure ASGI middleware (not `BaseHTTPMiddleware`): reads `X-Request-ID`; accepts it only if it matches `^[A-Za-z0-9._-]{1,64}$`, otherwise generates `uuid4().hex`; sets the context var; adds `X-Request-ID` to every response (including error responses); after the response, logs one access line with `method`, `path` (no query string), `status`, `duration_ms` (2 decimals) and `request_id`. Never logs headers, bodies, passwords or tokens.
- `JsonFormatter(logging.Formatter)`: one JSON object per line with `ts` (UTC ISO 8601), `level`, `logger`, `msg`, `request_id` (from the context var), any `extra` fields passed by the access log, and `exc_info` text when present. `ensure_ascii=False`.
- `configure_logging(level: str = "INFO")`: installs the formatter on a stdout handler of the `nutriguide` logger (named loggers `nutriguide.api`, `nutriguide.api.access`), sets `propagate = False`, idempotent (calling twice does not add a second handler). Do not reconfigure the root logger and do not touch uvicorn's loggers.
