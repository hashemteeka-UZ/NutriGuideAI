## 1. Encrypted database (#244)
- Replace `sqlite3_flutter_libs` with `sqlite3` 3.x build hooks and select SQLite3MultipleCiphers in `mobile/pubspec.yaml`:
  ```yaml
  hooks:
    user_defines:
      sqlite3:
        source: sqlite3mc
  ```
  Read `sqlite3/doc/hook.md` of the version you install and follow it exactly. If `sqlite3mc` is not available for android-x64 or the host test platform, STOP and report; do not fall back to an unencrypted database.
- Key: 32 random bytes from `Random.secure()`, hex-encoded, stored in `flutter_secure_storage` under `db_key_v1`, created on first open. Open with `NativeDatabase.createInBackground(file, setup: (db) { db.execute("PRAGMA hexkey = '<hex>'"); })` (key first, before any other statement), then verify with a simple `SELECT count(*) FROM sqlite_master`. Put this in `lib/core/db/` behind a `DatabaseKeyStore` interface so tests use a fake.
- Recovery: if the key is missing but a database file exists (e.g. the K.0-K.2 plaintext file, or Keystore lost after a device restore), delete the file (and `-wal`/`-shm`) and create a fresh encrypted one. If opening with the stored key fails, do the same. Nothing in the database is irreplaceable at this stage: the catalog re-downloads and the user data comes from the server.
- `schemaVersion` 2 with a drift migration strategy. Export schemas with `dart run drift_dev make-migrations` (or `schema dump` + generated migration tests per the drift docs) into `mobile/drift_schemas/`, and add the generated migration test.

## 2. Local tables (#245)
All catalog rows carry `lang` (`ar` or `en`) because the snapshot is language-specific; one language is replaced without touching the other.
- `catalog_meta`: `lang` PK, `etag`, `dataset_version`, `meal_count`, `fetched_at` (UTC).
- `meals`: (`lang`, `meal_id`) PK, `name`, `search_key` (section 4), `cuisine` (nullable), `dish_form` (nullable), `serving_grams`, `servings`, `total_grams`, `kcal`, `protein_g`, `carb_g`, `fat_g`, `source`, `dataset_version`.
- `meal_tags` (`lang`, `meal_id`, `tag`), `meal_allergens` (`lang`, `meal_id`, `code`), `meal_ingredients` (`lang`, `meal_id`, `position`, `ingredient_id`, `name`, `grams_per_serving`, `is_optional`), `meal_nutrients` (`lang`, `meal_id`, `code`, `unit`, `per_100g`, `per_serving`), `meal_steps` (`lang`, `meal_id`, `position`, `text`). Primary keys on the natural columns, foreign keys to `meals` with cascade delete, index on `meals(lang, search_key)`.
- `cuisines` (`lang`, `code`, `name`): written whenever `/reference` loads (the K.2 reference repository), so cuisine names work offline.
- User tables: `meal_prefs` (`meal_id` PK, `stance`, `updated_at`) and `user_allergens` (`code` PK, `severity`). These are personal and are deleted on logout and when another account signs in (hook into the K.1 local-first logout). The catalog tables stay.

## 3. Snapshot sync (#246)
- `lib/features/catalog/data/catalog_sync.dart`. The generated client cannot read response headers or accept 304, so make this ONE request with the app's `Dio` (same interceptors: auth, locale, logging): `GET /api/v1/catalog/snapshot`, header `If-None-Match` = stored ETag for the current language (omit if none), `Options(validateStatus: (s) => s == 200 || s == 304)`.
- 304: update `fetched_at` only. 200: parse with the generated `CatalogSnapshot.fromJson` inside `Isolate.run`, map to companions, and replace that language's rows plus `catalog_meta` in ONE transaction (all or nothing; a failed parse leaves the old copy untouched). Store the new `ETag` exactly as received.
- When: after the session is ready (app start with a session, and right after sign-in), when the locale changes, and on pull-to-refresh in the meals screen. Never blocks the UI. At most one sync in flight (share the running future). Network failure is silent when a local copy exists; with no local copy, the meals screen shows the empty state (section 5).
- Also on the same triggers, fetch `GET /me/meal-prefs` into `meal_prefs` (replace all) and the allergens from `GET /me/profile` into `user_allergens` (replace all; `PROFILE_NOT_FOUND` = empty). Right after the K.2 profile save, write `user_allergens` from the saved answers too.

## 4. Offline search and filters (#247)
- `lib/features/catalog/domain/search_normalizer.dart` (pure, unit-tested), applied to the stored `search_key` and to the query: Unicode NFC; remove Arabic diacritics (U+064B-U+0652, U+0670) and tatweel (U+0640); unify أ إ آ ٱ -> ا, ى -> ي, ة -> ه, ؤ -> و, ئ -> ي; Arabic-Indic digits -> ASCII; Latin lowercase; collapse spaces.
- Ranking: exact match, then prefix of the name, then prefix of any word, then contains; ties by normalized name, then `meal_id`. Run in drift (SQL `LIKE` on `search_key` with escaped `%`/`_`), debounced 200 ms. No trigram similarity locally (this is the only difference from the server's search; say so in a code comment).
- Filters (combine with search): slot chips «الكل / فطور / غداء / عشاء / خفيفة» mapped to occasion tags `breakfast_suitable`, `lunch_suitable`, `dinner_suitable`, `snack_suitable`; cuisine chips from the `cuisines` table (only cuisines present in the catalog); toggle «إخفاء ما يحتوي على ما أتجنبه», ON by default, hides meals that share any code with `user_allergens`. When OFF, those meals stay in the list with a warning badge.
- Repository returns domain models (`MealSummary`, `MealDetail` in `features/catalog/domain`), never drift rows, to presentation.
