## 1. Request-layer service `app/services/logging_requests.py` (#201, #202, #203)
Functions used by the routers (each takes `session, user_id, ..., now`):
- `create_log(body-equivalent args)` for the three kinds:
  - Time window (#202): `consumed_at` after `now + CLOCK_SKEW_TOLERANCE` (reuse the constant from `weight.py`) → `ClockSkewError` (`422 CLOCK_SKEW`). Its local date (user's timezone, existing `local_date`) earlier than local today − 30 days → `ValueError`-family error mapped to `422 VALIDATION_ERROR` with a clear detail. Put `LOG_HISTORY_DAYS = 30` in one place.
  - PLAN_ITEM: the local date of `consumed_at` must equal the item's plan date, otherwise `422 VALIDATION_ERROR`. Then `log_plan_item`. When the result is CREATED (not DUPLICATE), write one `user_interactions` row `ACCEPT` for the item's meal with context `{"plan_id", "plan_item_id", "slot", "algorithm_version", "servings_ratio"}` where `servings_ratio = servings_consumed / item.servings_multiplier` rounded to 3 places (#201). Its `client_uuid` stays null.
  - MEAL: `log_meal`; the meal must be active (inactive or unknown → `404 MEAL_NOT_FOUND`).
  - FOOD: `log_food` (#203). Never set `entry_group` or `entry_label`.
- `correct(...)`: the old log must be active and the caller's (`LOG_NOT_FOUND` otherwise). If `consumed_at` is given it obeys the same window, and for a plan-item log the same plan-date rule. Then `correct_log`. No new ACCEPT.
- `delete(...)`: `delete_log`; no interaction row.
- `logs_of_day(...)`: `active_logs`, mapped with names.
- Response mapping (`ConsumptionLogOut`): `kind` from which id is set; `name` through the same rules as `meal_catalog` for meals (language fallback) and `pick_name` for foods; `nutrients` from the stored snapshot; a nutrient missing from the snapshot is `null`, never 0 (§9.8). `status` from `LogResult`. Load names in batch for the day list (fixed query count; test it like I.4).
- Status codes: 201 on CREATED, 200 on DUPLICATE (set by the router from the status).
