## 1. Domain and data (#229, #230)
```
lib/features/auth/
  domain/session.dart              // sealed SessionState: SessionUnknown, SignedOut, SignedIn(account: AccountInfo?)
  domain/account_info.dart         // userId, email, createdAt, hasProfile (app model, not generated Account)
  domain/auth_repository.dart      // abstract: register, login, logout, currentAccount, restore
  data/token_store.dart            // abstract TokenStore + SecureTokenStore (flutter_secure_storage via core SecureStore)
  data/auth_repository_impl.dart   // uses generated AuthClient + AccountClient; mappers generated->domain
  data/auth_interceptor.dart       // QueuedInterceptor, section 2
  presentation/session_controller.dart  // Notifier<SessionState>, the single owner of session state
```
- `TokenStore` keeps: access token, refresh token, access expiry (absolute UTC, computed as now + `expires_in` seconds at receipt), and cached `has_profile`. Keys prefixed `ng.auth.`. Secure storage is the only place tokens are persisted (#229). The access token is also held in memory to avoid a Keystore read per request.
- If reading secure storage throws (Keystore can be invalidated after a device restore or lock-screen change), treat as signed out, delete all `ng.auth.` keys, and continue. Never crash on start.
- Startup (`restore`): no refresh token -> `SignedOut`. Refresh token present -> `SignedIn` immediately using the cached `has_profile` (works offline), then in the background call `GET /api/v1/me` to refresh `AccountInfo`; a network failure keeps the session, a `TOKEN_REUSED` / `TOKEN_INVALID` outcome signs out (via the interceptor, section 2).
- Register/login: on 200/201 save the token pair, then call `GET /api/v1/me`, cache `has_profile`, emit `SignedIn`. Trim the email and lowercase nothing else (the server owns normalization). Send it exactly as typed after trim.

## 2. Auth interceptor (#230) — the core of this pass
Implement as a `QueuedInterceptor` on the single app `Dio` (from `dioProvider`); the refresh call itself uses a **separate bare Dio** (same baseUrl/timeouts, debug log interceptor allowed, no auth interceptor) so a refresh can never recurse.
1. Public paths get no Authorization header: `/api/v1/health`, `/api/v1/reference`, and everything under `/api/v1/auth/`. Every other `/api/v1/` path gets `Authorization: Bearer <access>`.
2. Proactive refresh: if the access token expires within 60 seconds, refresh before sending.
3. Reactive refresh: on 401 with `code == UNAUTHORIZED` for a non-public request, refresh, then retry the original request **once** with the new token (mark the retry in `RequestOptions.extra` so it is never retried twice).
4. **Single flight:** concurrent requests that need a refresh share ONE in-flight refresh `Future`. Two parallel refreshes with the same refresh token would make the server see reuse and revoke the family (`TOKEN_REUSED`). Test this explicitly (section 7).
5. Persist the new pair immediately after a successful refresh, before retrying anything (rotation: the old refresh token is now dead on the server).
6. Refresh outcomes: success -> continue. `TOKEN_REUSED` or `TOKEN_INVALID` -> clear the token store, set session `SignedOut` with reason `sessionExpired`, fail the original request with that `ApiProblem`; never retry. `RATE_LIMITED`, network error, timeout, 5xx -> keep tokens and session, fail the original request with the mapped `AppFailure` (the user may just be offline).
7. A 401 `TOKEN_REUSED` on any request (not only refresh) also signs out.
8. `Accept-Language` header on every request from the current app locale (`ar` or `en`), set by a tiny interceptor or `BaseOptions.headers` updated when the locale changes. Not a generated parameter.
9. The session controller is told about sign-out through a callback or a provider the interceptor can read; avoid a provider cycle (interceptor -> controller -> repository -> dio -> interceptor). Describe the wiring in the report.
