## 1. Target time ordering (#214), do this first
Today `create_user_target` raises `TargetError` when `now <= current.valid_from`, and `profile._close_target` does the same. Both are unmapped, so they become 500. Real trigger: a sync batch shares one `now` for all operations, so two weight operations for the same latest day, each crossing `WEIGHT_RECOMPUTE_DELTA_KG`, open two targets at the same instant. The whole batch then 500s, nothing is committed, and the phone resends the same batch forever. A second trigger is two concurrent requests where the one holding the older `now` gets the row lock last.

- Add in `app/services/targets.py`: `TARGET_INSTANT_STEP: Final = timedelta(microseconds=1)` and `target_instant(current_valid_from: datetime, now: datetime) -> datetime` returning `max(now, current_valid_from + TARGET_INSTANT_STEP)`. PostgreSQL `timestamptz` keeps microseconds, so the step survives the round trip; add a test proving it.
- `create_user_target`: when a current target exists, compute `start = target_instant(current.valid_from, now)`, set `current.valid_to = start`, and open the new target with `valid_from = start`. Remove the "now must be after the current target's valid_from" raise.
- `profile._close_target`: `current.valid_to = target_instant(current.valid_from, now)`. Remove its raise.
- When `start != now`, write ONE warning line: user id and the word that the instant was advanced. No values.
- History stays append-only (no row is updated except `valid_to` of the closing row, as today), and `CHECK valid_to > valid_from` stays satisfied.
- Grep for any other `now <= ...valid_from` guard on targets and report it.
- `TargetError` itself stays (the non-positive macro guard is an internal invariant and stays 500).

Tests:
- `target_instant`: equal instants, `now` earlier than `valid_from`, `now` later (unchanged).
- Service: `create_user_target` twice with the same `now` gives two rows, the second `valid_from` = first + 1 µs, the first closed at that instant, exactly one open row. Same with a `now` 1 second before the current `valid_from`.
- Profile: a profile save that makes the user ineligible at the same `now` as the current target's `valid_from` closes it without error.
