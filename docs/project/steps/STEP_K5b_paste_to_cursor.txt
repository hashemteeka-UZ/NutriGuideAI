## 3. Weight (#271, #275)
- Weight sheet (from the quick sheet and from the Me tab): wheel 30.0-250.0 step 0.1, default = latest stored weight or the profile weight, unit «كغ», date = today.
- Online: `PUT /weights/{today}` directly with `updated_at` = now (an idempotent PUT per date). Show by response: `goal_reached` true -> celebration sheet «وصلت إلى هدفك!» (gendered ICU select) without confetti when reduce motion; `new_target_id` set -> notice «تم تحديث هدفك اليومي بناءً على وزنك الجديد» with «أعد بناء خطة الأيام القادمة» (calls the K.4 rebuild for days from tomorrow, which already skips logged days) and «لاحقًا»; then refetch `GET /me/targets`. `STALE_IGNORED` -> «يوجد وزن أحدث محفوظ لهذا اليوم».
- Network failure or offline: write the weight row PENDING and queue WEIGHT_PUT in one transaction, reusing the same `updated_at`. A newer weight for the same date replaces the queued op (delete old op, insert new). After a sync that confirmed a WEIGHT_PUT, refetch `GET /me/targets`; if the target id changed, show the same new-target notice.
- Me tab: the latest weight and «سجّل وزنك».

## 4. Logging another catalog meal (#272)
- «أكلت وجبة أخرى» opens a picker on the local catalog (reuse the K.3 search and list tiles; allergen-unsafe meals keep their K.3 warning badge, they are not hidden).
- Then a sheet: servings ½, 1, 1½, 2 (default 1), slot = the current meal window or a chooser of the four slots, consumed_at = now, today only.
- Queue CONSUMPTION_CREATE with log kind MEAL (`MealLogCreateOp` from K.5a) and write a `consumption_logs` row (kind MEAL, `plan_item_id` null) in one transaction.
- Provisional values for a PENDING MEAL log = the snapshot meal's per-serving server kcal/protein/carb/fat × servings_consumed. Server values replace them after sync.
- Today shows a section «إضافات اليوم» under the timeline with each MEAL log (name, portion, kcal, state) and «تراجع» (compaction rule). Off-catalog free text and FOOD (ingredient) logging stay postponed: no entry point.
